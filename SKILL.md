# Blibli Seller API Guide

Use this skill to answer exact Blibli Seller API structure questions and avoid
guessing fields.

## Coverage

- Platform: Blibli Seller API (`seller-api.blibli.com`)
- URL shape: `/docs/services/{serviceId}/operations/{operationName}`
  (e.g. service 66 → Seller API, service 79 → Webhook API, service 65 → SAS).
- 27 category folders under `references/api/` (Product, Order, Order Return,
  Settlement, Queue, Blibli Promo, Bliklan, Seller Discount, Seller Voucher,
  Seller Promo Purchase Deals, Store Management, Product Discussion, Seller
  Chat, Click & Collect, Webhook History, plus Webhook * and Deprecated/Obsolete
  API), 189 API docs total.
- Each doc has YAML frontmatter (`category`, `api_name`, `method`, `url`,
  `date_saved`) plus structured sections: `# <Operation name>`, `### Overview`,
  `### Header`, `### Parameter`, `### Sectioning`, and parameter/response tables.
- Webhook APIs (service 79 categories) document push notification payloads and
  headers (Authorization basic auth, requestId, requestTime, token, Signature).

## Workflow

1. Read the request and identify the business capability and any explicit method/path/version.
2. Map the capability to a category (e.g. product create → `Product`, order list → `Order`, webhook order → `Webhook Order`).
3. Inspect `references/api/<Category>/<operationName>.md` for the matched API.
4. Search `references/api/` by operation name, endpoint path, or keyword when the category is unclear.
5. Read the exact method (`POST`/`GET`/`PUT`/`DELETE` in frontmatter/body), the HTTP path
   (e.g. `/seller/v1/products/filter`), and the Header / Parameter / Sectioning tables.
6. Do not silently substitute a nearby operation with a different version suffix
   (e.g. `V1` vs `V2`).
7. If a schema, policy, deprecation, or newer version is not present in the local
   reference, check the official Blibli Seller API docs
   (`https://seller-api.blibli.com/docs`) and state the gap/source.
8. Do not invent fields, enum values, required flags, or response shapes that are absent
   from the selected API's official schema.

## References

- `references/api/<Category>/<operationName>.md` — one clean Markdown doc per Blibli API.
- Category folders map to Blibli categories (e.g. `Product`, `Order`, `Settlement`,
  `Webhook Order`, `Store Management`).

## Update & Provenance

- Local reference is a **static snapshot**. It is regenerated by the toolchain in the
  `updskills` repo (`tools/bulk_render_blibli.py`) which pulls the official
  `sections` manifest from
  `https://seller-api.blibli.com/backend/documentation/sections` and re-renders every
  operation page. To get fresher APIs, re-run that tool rather than hand-editing.
- For agent use, prefer the official live docs for anything that may have changed
  since this snapshot (deprecations, new scopes, policy).
